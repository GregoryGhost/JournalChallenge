# Subtask: EF Bundle & Migration Runner Setup (stt-005)

## Objective
Implement the "Same Image, Different Entrypoint" pattern to ensure the database is fully initialized before the API starts.

## Actions
- [x] Modify the `Dockerfile` to:
    - [x] Install `curl` in the base image (required for Docker native health check).
    - [x] Install `dotnet-ef` tool in the build stage.
    - [x] Generate an EF migration bundle (`efbundle`) during the publish stage.
    - [x] Copy the `efbundle` into the final runtime image.
- [x] Update `docker.testing.yaml` to:
    - [x] Add a `migrate` service that uses the API image.
    - [x] Override the `migrate` service entrypoint to run `./efbundle`.
    - [x] Make the `api` service depend on `migrate` completing successfully.

## Verification
- Run `docker compose -f docker.testing.yaml up --build --exit-code-from newman`.
- Confirm the `migrate` service finishes successfully before the `api` starts.
- Verify the "database does not exist" error is resolved.
