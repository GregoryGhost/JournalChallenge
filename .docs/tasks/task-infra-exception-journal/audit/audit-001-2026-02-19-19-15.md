## 1. Summary of Work
The global exception journaling system has been fully implemented and verified. This includes the database schema, domain logic for error mapping, a capture middleware in the presentation layer, and the application logic for retrieving journal entries.

## 2. Key Features Implemented

### 2.1 Infrastructure & Middleware
- **ExceptionMiddleware**:
    - Generates unique `long` Event IDs using `DateTime.UtcNow.Ticks`.
    - Buffers the request body to allow logging even if the stream was already read.
    - Captures and stores Query and Body parameters as JSON in the database.
    - Formats the HTTP 500 response body according to the `SecureException` and general `Exception` rules specified in `spec.md`.
- **CustomResultsHandler**:
    - Maps `ErrorType.Secure` to `SecureException`.
    - Maps other `DomainError` types to standard `Exception`.
    - Integrated with the `ValidationDecorator` and `LoggingDecorator` pipelines.

### 2.2 Application Layer (Journal Retrieval)
- **Feature: Get Journal Range**:
    - Paginated retrieval with `skip`/`take`.
    - Filtering by date range (`from`/`to`) and keyword search.
- **Feature: Get Single Journal Entry**:
    - Detailed retrieval by entry ID.
    - Combines message and stack trace into the `text` field as per Swagger requirements.

## 3. Verification & Testing
- **Unit Tests**: Added 10 new test cases (6 handler logic, 4 validation) across the new features. All tests passed.
- **End-to-End Integration**:
    - Verified that unhandled exceptions correctly trigger the middleware.
    - Verified that details are persisted to the PostgreSQL database with full context (query/body/stacktrace).
    - Verified the JSON response format matches Section 3.1 and 3.2 of the specification exactly.
    - Verified API routes match the Swagger definition (e.g., `api.user.journal.getRange`).

## 4. Architectural Notes
- The solution strictly follows the **Feature-per-Folder** organization for handlers, validators, and tests.
- Uses `IServiceScopeFactory` in the singleton middleware to safely interact with the scoped database context.
- Ensured PostgreSQL `jsonb` compatibility by defaulting empty parameters to `"{}"`.
